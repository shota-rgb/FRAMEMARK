## スライド 3｜ツール概要 — FRAMEMARKとは

**YouTubeチャンネルのディレクターと動画編集者の間で、タイムコード付き修正指示を送り合うための動画レビューWebサービス。**

### 解決する課題

| 従来の問題 | FRAMEMARKの解決策 |
|---|---|
| メール・LINEで修正指示がバラバラ → 見落とし発生 | すべての指示をプラットフォーム上で一元管理 |
| 「どの場面か」が伝わらない（時間指定が曖昧） | タイムコード付きコメントで該当シーンにピンポイント指示 |
| 最新版がどれかわからない → ミスが起きる | バージョン管理でV1/V2/V3を自動整理 |

### ターゲットユーザー

- **ディレクター**（発注側）：動画をレビューし、修正指示を出す
- **編集者**（受注側）：修正指示を受け取り、修正版を納品する

## スライド 4｜主な機能

### 機能① タイムコード付きコメント
- 動画再生中の任意のタイムコードにコメントを紐付け
- コメントをクリックするとその時間に自動シーク
- 返信・解決済みマーク対応

### 機能② マーキング & アノテーション
- ペン・四角・円・矢印・テキストで映像に直接書き込み
- アノテーションはコメントと一緒に保存・再表示
- 画像添付コメントにも対応

### 機能③ バージョン管理
- 動画のV1→V2→V3を自動管理
- ステータス管理：初稿 → レビュー中 → 修正依頼済 → 修正済 → 校了
- 過去のバージョンをクリックで再生可能

### 機能④ ワークスペース & メンバー管理
- ディレクターがワークスペースを作成
- 招待リンク発行でメンバーを招待（メール不要）
- 未読バッジで「要対応」動画を一目で把握

## スライド 5｜操作マニュアル — ディレクター編

```
① サインアップ
   → 「ディレクター」を選択してアカウント作成
   → 組織名を入力（ワークスペースが自動作成される）

② メンバー招待
   → サイドバー「メンバー管理」から招待リンクを発行
   → リンクを編集者に共有するだけ（メール送信不要）

③ 動画のアップロード
   → 「アップロード」から動画ファイルを選択してアップロード
   → サムネイルは自動生成（先頭フレームをキャプチャ）

④ レビュー申請（編集者に確認依頼）
   → 動画詳細画面でステータスを「レビュー中」に変更

⑤ 修正指示の確認・返信
   → 編集者からのコメントにタイムコードで返信
   → アノテーションで視覚的に補足

⑥ 修正版の確認
   → サイドバーのバッジで「修正済」動画をすぐ把握
   → バージョンセレクターで過去版と比較再生

⑦ 校了
   → 「校了」ボタンで完了。必要であればファイル削除も選択可能
```

---

## スライド 6｜操作マニュアル — 編集者編

```
① アカウント作成
   → ディレクターから届いた招待リンクを開く
   → 「編集者」でサインアップ → 自動的にワークスペースに参加

② 動画一覧の確認
   → ダッシュボードで担当動画を確認
   → 「要対応」バッジで対応が必要な動画をすぐ把握

③ 修正指示の確認
   → 動画詳細でタイムコード付きコメントを確認
   → コメントをクリックすると該当シーンに自動ジャンプ
   → アノテーション（書き込み）も合わせて確認

④ 修正版のアップロード
   → 「新しいバージョンをアップロード」からV2を提出
   → ステータスが「修正済」に更新され、ディレクターに通知

⑤ 校了まで繰り返し
   → ディレクターが「校了」にしたら完了
```

## スライド 10｜データベース設計

```
workspaces（ワークスペース）
  └─ workspace_members（メンバー・招待管理）
  └─ videos（動画メタデータ・ステータス）
       └─ video_versions（V1/V2/V3 ファイルパス管理）
       └─ comments（タイムコード付きコメント・返信・画像）
            └─ annotations（Canvas描画データ JSONB）
  └─ comment_templates（修正指示テンプレート）
  └─ notifications（通知）
  └─ video_status_seen（既読管理）
```

### VideoStatus の遷移

```
初稿(draft) → レビュー中(review) → 修正依頼済(revision_requested)
                                        ↓
                              修正済(revised) → 校了(approved)
                              
任意のタイミングで → 終了(cancelled)
```

## スライド 11｜セキュリティ設計

### Row Level Security（RLS）
- **全テーブルでRLSを有効化**。SQLポリシーにより、ユーザーは自分が所属するワークスペースのデータのみアクセス可能
- 相互参照による無限再帰を `SECURITY DEFINER` 関数で回避

### ストレージ
- 動画・画像バケットはすべて**非公開（プライベート）**
- ファイルアクセスは署名付きURL（Signed URL）のみ。有効期限1時間

### 認証
- Supabase Auth による JWT 認証
- 未認証アクセスはプロキシで `/login` にリダイレクト

## スライド 12｜AI開発を通じた考察

### できたこと

- **フルスタックSaaS を2日で本番稼働**
  DB設計・認証・UI・デプロイまですべてAIが担当

- **技術的な意思決定もAIが提案**
  「RLSの無限再帰をどう回避するか」「サムネイル取得にどのイベントを使うか」など、経験が必要な判断もAIが適切な解を提示

- **コードレビューとデバッグの高速化**
  エラーメッセージを貼り付けるだけで原因と修正コードを即提示

### 人間が担った役割

| 役割 | 内容 |
|---|---|
| 意思決定 | 何を作るか、どの機能を優先するか |
| レビュー | AIの提案が要件を満たしているかの確認 |
| テスト | 実際にブラウザで動作確認 |
| コンテキスト提供 | 「なぜこうしたいか」の背景をAIに説明 |

### 課題・注意点

- AIは「現在の状態」を把握しているが、文脈が長くなると一貫性が薄れることがある
- 「動くコード」は生成できるが、設計の妥当性は人間がレビューする必要がある
- Next.js 16系など学習データに少ない最新技術は、AIが誤った情報を提示することがある（都度検証が必要）
